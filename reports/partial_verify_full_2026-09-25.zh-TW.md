## 3. 為什麼 FAIL 幾乎都偏高：期望值慣例的對照（描述用、非 GATE）

腳本 `partial_offset_decomposition.py` 做的事：對每個量到的泛音，把兩個數字並排。

- 工具量到的偏差：跟第 0 根弦比。
- 3 根弦的加權平均比第 0 根高多少：權重用各弦振幅，跟 `verify_score.course_f0()` 對基頻的算法相同，數字從同一支 CLI 的 `--dump-modes` 讀。

它不改任何判定。

- 這首的每顆音都是 3 根弦，分別在第 0 根的 0／+5.00／+10.00 c。這是引擎預設的 detuning 5 cents（`src/score/ScoreParser.h:79`），score 沒有另外設定。工具的 caveat 本來就寫明「partial 期望值取第 0 根弦、不是 3 弦中心」。

| 對象 | 個數 | 中位數 | 5%～95% 範圍 | 最大 |
|---|---:|---:|---|---:|
| 工具量到的偏差（對第 0 根弦） | 5426 | +4.45 c | +2.02～+6.33 c | +12.39 c |
| 3 弦平均比第 0 根高多少 | 5426 | +4.99 c | +4.55～+5.65 c | +8.23 c |
| 兩者相減 | 5426 | −0.48 c | −2.17～+0.28 c | +5.89／−9.67 c |
| 只看工具判 FAIL 的 849 個：兩者相減 | 849 | +0.03 c | −0.29～+3.53 c | +5.89 c |

讀法：

- 工具判 FAIL 的那些，扣掉 3 弦平均的 +5 c 之後，中位數只剩 +0.03 c。大部分 FAIL 是慣例差造成的。
- 換一個慣例也不會變乾淨。如果期望值改用 3 弦平均，同樣 ±5 c 下有 120 個超出（其中 116 個目前是 PASS）：
  - 97 個是 A2 的 n=1。A2 基頻 110 Hz，量測器在低音區會把讀數往期望值拉，這是既有的已知缺口（設計文件 §8.5「期望值固定、真值另外偏離」那條增益軸：MIDI 37 真實 +40 c 只量到 +23.14 c）。所以 A2 量到的值貼近第 0 根弦（−0.81 c），不是量到真的偏差。
  - 其餘分散在高音的 n=5～6，以及少數中音。
- 相關係數 r = 0.64（量到的偏差 vs 3 弦平均的偏移）。
- 結論（描述用）：849 這個數字主要反映工具的期望值慣例。至於要改用哪個慣例、或乾脆維持 informational，是工具規格的決定，本卡不動（§7「期望值慣例」那一點）。
