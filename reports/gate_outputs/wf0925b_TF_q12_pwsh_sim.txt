包法出處（本卡 2026-09-25 讀網頁核對，只讀、沒下載任何執行檔）：
- actions/runner 原始碼 src/Runner.Worker/Handlers/ScriptHandlerHelpers.cs：
  預設參數 pwsh = `-command ". '{0}'"`、bash = `--noprofile --norc -e -o pipefail {0}`；
  FixUpScriptContents 對 pwsh/powershell 在腳本前面加 `$ErrorActionPreference = 'stop'`、
  後面加 `if ((Test-Path -LiteralPath variable:\LASTEXITCODE)) { exit $LASTEXITCODE }`。
- GitHub Docs「Workflow syntax」shell 表：不指定 shell 時非 Windows 是 `bash -e {0}`。
模擬怎麼做：
- 從 YAML 取出每個多行 run 區塊，照上面的包法寫成暫存 .ps1，用 `pwsh -NoProfile -command ". '<file>'"` 跑
  （-NoProfile 只是避免本機 profile 干擾）；bash 區塊用 Git Bash 照對應參數跑。
- python、ctest、cmake、git、sudo、HostProbe exe 全部換成 PATH 最前面的樁（stub）：印出自己的指令列，
  指令列含 FAIL_MATCH 就 exit 7，否則 exit 0。沒有真的建置、沒有真的下載（pluginval 的 Invoke-WebRequest
  那步和 validate_plugin.ps1 那步沒有原生指令，不模擬，另外說明）。
- 每個原生指令輪流「只讓它失敗」，記錄整步的 exit code。整步 exit 0 但裡面有指令失敗＝MASKED（被蓋掉）。
- 為什麼失敗時整步是 1 不是 7：pwsh 的 -Command 模式會把「最後一個指令是 exit N（N 不是 0/1）」的結果轉成 1，
  這是 PowerShell 文件寫的行為，GitHub 上的 pwsh 步驟失敗也是顯示 exit code 1；判斷只看 0 或非 0。
- 單行 run 不模擬：runner 包法最後的 `exit $LASTEXITCODE` 就是那一個指令的結果，不可能被別的指令蓋掉。
- 另外兩個 .ps1（tools/run_asan_ctest.ps1、tools/validate_plugin.ps1，本卡沒改）有讀過：失敗時都用 throw，
  在 'stop' 下是終止錯誤，整步一定非 0。
