- user preset 實際路徑：
  juce::File::getSpecialLocation(userApplicationDataDirectory)
    .getChildFile("TsukiSynth").getChildFile("Presets")
  == %APPDATA%\TsukiSynth\Presets\*.tsukipreset （src/PresetManager.h
  getPresetDirectory()，本卡未改動這個路徑）。
  檔案格式：XML root <TsukiSynthPreset name=".." id=".." version="2">，
  單一 child = apvts.copyState() 的 XML（saveUserPreset()）。改動前這個
  child 是「唯一」child——IR 完全沒有位置可記。

- DAW state 現況（改動前）：TsukiSynthProcessor::getStateInformation() 在
  apvts state 上多設一個 flat property "reverb_ir_path"（使用者機器上的
  絕對路徑字串，無雜湊、無原始檔名）；setStateInformation() 讀回這個路徑
  直接呼叫 loadReverbIRFile(path, ..., switchModeToIR=false)——檔案不存在
  就照 loadReverbIRFile 的「File not found」失敗路徑安靜跳過（呼叫方沒接
  error），fx_reverb_mode 維持存檔時的值（可能還是 Impulse Response），
  等於「按鈕聲稱 IR、音訊其實在跑 algorithmic」——這正是本卡要修的雙軌
  （docs/AUDIT_STRUCTURAL_FINDINGS_2026-08-31.zh-TW.md §1 第二列）。

- Load 鈕現況（改動前）：src/PluginEditor.cpp 只有一顆 revLoadButton，
  FileChooser filter "*.json;*.wav"，callback 依副檔名分派到
  loadReverbIRFile()（.wav）或 loadReverbProfileFile()（.json）——
  審計文件點名的心智模型混淆：使用者看到一顆「Load」，不知道自己在載入
  的是 IR 音訊還是殘響參數設定檔。

1. 設計落地摘要（對照卡 §2）
======================================================================

- src/IRLibrary.h（新）：%APPDATA%\TsukiSynth\IR\<sha256 前 32 碼>.wav +
  同名 .json metadata；importFile()/resolve()/list()；IRRef.kind 預留
  user/factory（factory 本卡不實作，已確認 data/、BinaryData 無工廠 IR
  資產）。SHA-256 自帶實作（FIPS 180-4，經 Python hashlib 對照 ""/"abc"/
  pangram 三組向量驗證一致），未新增 CMakeLists 模組相依。
- 三態載入：TsukiSynthProcessor::restoreReverbIR()/tryLoadIRRef()
  （src/PluginProcessor.{h,cpp}）。
    吻合：resolve 找到檔，內容雜湊核對通過 -> 靜默載入。
    庫被改寫／指了別的檔：resolve 依檔名找到檔，但實際內容雜湊與 preset
      記的不符 -> 照樣載入，reverbIRMismatch=true（不靜默頂替）。
    缺檔無 GUI：resolve 找不到檔 -> effectChain.clearImpulseResponse()、
      fx_reverb_mode 強制切回 Algorithmic、reverbIRMissing=true、跳一次性
      警告（措辭比照決策包 §7.2/§7.6：報原始檔名＋講明「音量會和 IR 模式
      不同」，K-02 未量化前不補係數，R4）。
- 兩條紅線：restoreReverbIR() 一律先 clearImpulseResponse() 才決定要不要
  載入（紅線一，永不沿用 instance 既有 IR）；IRStatus::loaded 直接賦值
  = effectChain.hasImpulseResponse()（同一個欄位，非兩個變數，紅線二，
  結構上保證恆成立）。
- 單一真相 / 序列化：PresetManager 新增 getExtraStateBlock /
  applyExtraStateBlock 回呼（src/PresetManager.h），preset 序列化變成
  「APVTS state + 可選附加 ValueTree」，PresetManager 本身仍不知道
  "reverb_ir" 是什麼（IR-agnostic）。getStateInformation()/
  setStateInformation()（DAW state）改用同一個 reverb_ir 區塊，並額外寫入
  ir_missing/ir_mismatch 兩個 informational 快照供 HostProbe 讀。
- UI：PluginEditor.{h,cpp} 把 .wav/.json 共用的 Load 鈕拆成兩顆
  （revLoadButton=IR .wav、revLoadProfileButton=Profile .json）；面板標題
  改讀 getIRStatus()，missing 顯示「未載入：<原始檔名>」、mismatch 顯示
  「與 preset 存的不是同一個 IR」；一次性警告由 editor 20Hz timer 輪詢
  proc.getAndClearIRWarning() 彈出 NativeMessageBox。
