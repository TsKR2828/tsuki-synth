## 0. 白話結論

1. **CLI 完全沒變。** 修前、修後兩版 CLI 渲染 8 首，SHA256 都跟基準 `sha256_before_post_a14.txt` **8/8 一樣**。原因：CLI 每個音只用一顆 voice，只放一次鍵，修法改到的那條路 CLI 根本不會走。
2. **殭屍 voice 幾乎消失。** 月光全曲（FM）在「voice 不限量」時，同時要的 voice **從 196 顆降到 14 顆**。最高點那一刻，音量已經低於 24-bit 最小一階（−138.5 dB 參考線）的殭屍 **從 184 顆降到 0 顆**。用 V1 的模型重算、用真的 FM 程式碼實測，兩邊結果一樣。
3. **16 顆的 pool 不會再被塞滿。** 月光全曲在外掛 16 顆 pool 裡：
   - 被搶的音：**798 次 → 0 次**。
   - pool 全滿的時間：**89.9 秒 → 0 秒**。
   - 修前被搶的音裡，有 94 次被搶時音量還在 −10 dB 以內（同一個音剛放鍵就重打）。被搶等於 5 ms 硬切，修後沒有這種硬切。
4. **聲音會變，但只在「FM 外掛＋同一個音反覆」的時候變。**
   - 月光全曲外掛整體 RMS：−19.126 → −19.118 dBFS（差 0.008 dB）。
   - 但逐 sample 最大差到 0.389（−8.2 dBFS）。這些大差異集中在修前「被搶、硬切」的地方：差異能量有 59% 落在修前硬切掉還聽得到的音之後 0.2 秒內，而這些時段只佔全曲 2.6%。
   - 同音反覆的尾巴會比修前短一點。例：給愛麗絲開頭 FM 版的尾段能量少 1.3 dB。
   - 沒有同音重疊的曲子（對照組 S3），外掛輸出**位元完全不變**。
5. **CPU 變省。** 月光全曲兩版外掛各跑 6 次：修前約佔即時的 2.69～2.71%，修後約 2.21～2.23%，少約 18%。原因是不用再算那些殭屍 voice。
6. **有一件事還沒解釋**：合成測例 S4（同一個音「按著還沒放就重打」、release 1.5 s）修後整體 RMS **大了 1.5 dB**。不經過效果器的乾聲測量也一樣大 1.5 dB。目前推測是多顆同音高 voice 疊在一起時，相位互相抵消。**沒有證實**，列在 open_items。
7. 踩延音踏板的情境（AI Radiance 全曲 FM 19 顆、第三樂章 17 顆）**修法沒有幫助**：修前修後完全一樣。那是 pool 大小的問題（Q09 選項 A 的範圍），跟殭屍無關。

## 2. patch 內容說明

檔案：`reports/wf1002_fm_envelope_fix.patch`。只改 `src/dsp/Envelope.h` 的 `noteOff()`，淨增 13 行，其中 7 行是註解。已在主 repo 做過 `git apply --check`，可以乾淨套用（只檢查，沒有套）。

**原本的行為**
- 只要 envelope 不是 Idle，`noteOff()` 每次都從「目前音量」重新起算整段 release。
- JUCE 每次同音按下或放開，都會對這個音號的**每一顆** voice 送一次「收尾」。
- 所以一個已經在收尾的舊 voice，每被同音打到一次，release 就重新開始一次。
- 同音反覆的間隔比 release 短時，舊 voice 永遠到不了 Idle，一直佔著位子。

**修後的行為**
- 已經在 Release 的 envelope，再收到 `noteOff()` 時**不重算**，照原本的斜率繼續降到 0。
- **唯一例外**：新的 release 比剩下的還短時，仍然改用短的。這是為了保留 `FMPianoVoice::stopNote()` 搶音或全部靜音時那個 **5 ms 硬切**。

**為什麼要保留這個例外**
- 如果寫成「在 Release 就一律 return」，被搶的 voice 雖然已經 `clearCurrentNote()`，但 envelope 還在跑，會繼續把原本那段慢慢的尾巴算完。
- 這樣硬切就不見了，等於多改了一個行為。

**例外確實跟修前一樣的證據**
- AI Radiance 全曲 FM 踩踏板的情境：兩版都搶 7 次，其中 6 次搶到的是 Release 中的 voice。
- 外掛輸出兩版**位元完全一樣**。

**不受影響的部分**
- 第一次放鍵（Attack／Decay／Sustain → Release）的算式、數值、型別都跟原本逐字相同。
- 這就是 CLI 8/8 不變的程式碼理由。CLI 的實測見 §3.1。

## 4. 會改到哪些情境

**只會在全部條件同時成立時改變輸出**
- 外掛（VST3／Standalone），而且
- 引擎選 **FM Piano**，而且
- 有一顆 voice **已經在收尾（Release）時，又收到一次收尾**。

**實際上是這幾種情況**
1. 同一個音在前一顆還沒收完尾時又被按下：S1、S2、月光第三樂章那段、給愛麗絲 E5-D#5 反覆。
2. 同一個音「按著還沒放就重打」：重打時舊的那顆會先被收尾，等它自己的放鍵訊號再來時已經在 Release（S4）。
3. 放開延音踏板、全部音關閉（CC123）、切換引擎時，對已經在收尾的 FM voice 再收一次尾。

**不會改變的**
- CLI 渲染：8/8 已驗證，程式碼路徑也證明不會走到。
- Cimbalom、Piano、Chromatic 引擎：它們只用 `Envelope::ExpDecay`，這次沒有改。
- FM 引擎一般單音彈奏，或同一個音的間隔大於「時值＋release」（S3 位元相同）。
- 搶音的 5 ms 硬切（AI Radiance 踩踏板情境位元相同）。
- 全程踩踏板的情境：踏板踩著時，放鍵不會觸發收尾，殭屍不會累積。修前修後一樣，修法也解決不了 19 顆／17 顆的問題。

**聽感上的方向**
- 同音反覆時，舊音的尾巴不再被一直拉長。
- 修前，pool 塞滿後會硬切「剛放鍵、音量還大」的同音；修後沒有這種硬切。

**如果不放行**
- 外掛維持現狀，照 Q09b 選項 B 的寫法把限制寫進主張域。

**風險**
1. **外掛輸出會變**（R10 的本意）。
   - 用舊版外掛做過的 DAW 專案，用新版重新匯出時，FM 軌在同音反覆的地方不會位元相同。

   - 如果月月在意，可以再開一張唯讀卡，逐顆 voice 拆能量來證實。
3. **鏡像不是外掛本體。**
   - voice 數、被搶次數是用同一份 header 的鏡像量的，不是從 VST3 內部讀的。
