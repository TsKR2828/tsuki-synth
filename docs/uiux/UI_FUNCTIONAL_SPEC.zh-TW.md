## 1. 產品是什麼、誰在用

**是什麼**：一個用物理理論模擬樂器發聲的軟體合成器（VST3 外掛 + 可獨立執行的 Standalone）。
使用者按 MIDI 鍵盤或用 DAW 播放，它算出聲音。它模擬四種樂器：
揚琴（弦）、空靈鼓／水鑼（板與梁）、FM 電鋼琴（非物理，訊號合成）、鋼琴（弦＋槌）。

**誰在用**（兩種人，設計必須同時服務）：

1. **作者本人（月月）是聾人。** 她**聽不到**這個軟體發出的任何聲音。
   所有回饋必須是**看得見的**。任何「調到聽起來對為止」的設計都對她無效。
   她需要看到：現在發的是哪個音、音高偏差幾音分、波形／頻譜長什麼樣、
   參數現在是多少、哪個參數被改過。
2. **一般聽得見的音樂人**（產品要賣給他們）。他們的期待是：
   打開就能選音色、旋鈕好轉、跟其他合成器的操作習慣一致、能存自己的音色。

**這兩種人的需求不衝突**：對聾人足夠的視覺回饋，對聽得見的人只是額外的資訊。

## 2. 硬性約束（功能性，非樣式）

| # | 約束 | 為什麼 |
|---|---|---|
| C1 | **不得有任何「只能用聽的」互動。** 每個會改變聲音的動作都要有對應的視覺結果。 | 主要使用者是聾人 |
| C2 | **必須能在一般筆電螢幕上完整使用，不被裁切、不需捲動才能按到主要控制。** 現行版本因為最小高度需求過大，在 Mac 筆電上放不下——這是這次重設計的直接觸發原因。（不指定尺寸：由設計端決定怎麼達成。） | 現行版本實際塞不下 |
| C3 | **視窗可由使用者縮放**，且縮放後仍可用。 | 外掛在不同 DAW 視窗裡尺寸不一 |
| C4 | **同一份設計要同時活在兩種容器裡**：DAW 內的外掛視窗、以及獨立執行的桌面程式。獨立版多出兩個功能（見 F11），外掛版不顯示它們。 | 兩種建置目標 |
| C5 | **全介面中／英雙語即時切換**，切換不重開視窗。目前有 33 組介面字串。 | 已實作的功能，不可掉 |
| C6 | **所有 60 個聲音參數都要能被 DAW 自動化與存檔**，因此每一個都必須是「一個明確的、可回讀的控制項」，不能是純視覺的裝飾或只存在於某個彈出層裡而無法被指到。 | DAW 相容性 |
| C7 | **參數值必須看得到數字或明確刻度**，不能只有一個沒有讀數的指針。 | 聾人無法靠聽判斷，只能靠讀值 |
| C8 | **小字必須有放大機制**（現行做法是滑鼠停留時浮出大字泡泡；做法可換，功能不可掉）。 | 無障礙 |

## 3. 使用情境（請先讓這幾條路順）

**J1 — 我要快速試音色**
開啟 → 看到現在是哪個樂器 → 從音色清單挑一個（27 個原廠音色）→
用畫面上的鍵盤點幾個音 → 看到波形動 → 換下一個。
（全程不需要碰任何旋鈕。）

**J2 — 我要調出自己的音色**
選樂器 → 先動 8 顆「總體感覺」旋鈕（材質／張力／阻尼／敲擊……）→
不夠就進該樂器的細節參數（例如揚琴的弦徑、每組幾條弦、失諧量）→
加效果（殘響／延遲／壓縮／破音／EQ）→ 存成自己的音色。

**J3 — 我改壞了，想回到原點**
需要看得出「我改過了」（現行有一個 dirty 標記），並能一鍵回到初始狀態。

**J4 — 聾人的驗證流程（本專案獨有，優先級高）**
彈一個音 → 看調音表：目標頻率、實際偵測到的頻率、差幾音分 →
判斷這個引擎有沒有把音高做對。放開琴鍵後最後一次量測要**留在畫面上**，
不能一鬆手就消失（不然來不及看）。

**J5 — 我要把一整首曲子渲染成音檔**（只有獨立版）
開啟樂譜主控台 → 選一份樂譜檔 → 按渲染 → 看進度與訊息 →
打開輸出資料夾／打開產生的 HTML 驗證報告。

**J6 — 我要錄下我現在彈的東西**（只有獨立版）
按錄音 → 錄 → 停止 → 檔案落到磁碟；錄音中要看得出來正在錄。

## 5. 狀態與顯示邏輯（設計必須處理的分支）

1. **引擎切換**：選了哪個引擎，就只顯示那個引擎的專屬參數；其他三組不該同時佔位。
   Macro 8 顆與所有效果器**不隨引擎改變**，永遠在。
2. **Chromatic 的子引擎**：選「自訂 Custom」時那 16 個泛音參數才真正有意義；
   選空靈鼓／水鑼時它們是被物理模型接管的。設計要能表達「這組現在不主導」。
3. **殘響模式**：切到「脈衝響應」後，「載入 IR 檔」才有意義；
   沒載入 IR 就切過去時要有明確狀態顯示。目前**同一顆按鈕同時吃兩種副檔名**
   （`.wav` 的 IR 與 `.json` 的殘響設定檔），已知會造成混淆——重設計時請拆開或講清楚。
4. **EQ 增益 = 0 dB** 與 **殘響 T60 = 0 秒** 是「不作用」的特例值，
   使用者要能看出「我現在是關的」而不是「我設了一個很小的值」。
5. **外掛 vs 獨立版**：獨立版多出錄音與樂譜主控台兩塊，外掛版整塊不存在。
6. **改過標記**：任何參數一動就要能顯示與音色不同步的狀態。

## 6. 誠實揭露：以下東西現在**不存在**（不要照想像設計）

| 項目 | 實情 |
|---|---|
| 「揚琴左右手強弱」 | **沒有這個參數**。舊 mockup 裡的它只是視覺佔位。要做得先加參數與 DSP，屬另一張卡。 |
| 樂器的視覺模擬畫面（畫出琴弦／鼓面／琴鍵並會動） | **從來沒有做過**，舊參考原型裡也沒有。若這次要做，它是**全新功能**，不是復原。 |
| 空靈鼓獨奏可商用 | 引擎目前有缺陷（同力度下高低音響度差 40 dB、泛音幾乎沒有），設計上不要把它當成招牌樂器展示。 |
| IR 殘響存進使用者音色 | **目前是 bug**：IR 設定進得了 DAW 專案檔，但進不了使用者音色，重載會靜默退回演算法殘響。設計時若要呈現「音色包含殘響」，要知道底下這件事還沒修。 |
| 音色的預覽試聽 | 沒有。（且對主要使用者無效——見 C1。） |

## 7. 交付回來時的驗收問題（設計端請自行先過一遍）

1. 60 個聲音參數是不是每一個都能被指到、看到值、被 DAW 自動化？（C6/C7）
2. 一般筆電螢幕上，主要工作（J1、J2）是不是不用捲動就能完成？（C2）
3. 聾人要驗證音高（J4），是不是三步以內就能看到「差幾音分」？
4. 16 個泛音參數有沒有被當成「一組」處理，而不是 16 顆散落的旋鈕？
5. 切換引擎時，畫面是不是清楚地換了一組東西，而不是整頁重排到認不出來？
6. 中英切換後有沒有任何文字被截斷或跑版？（C5）
7. 獨立版多出來的兩塊，拿掉之後外掛版是不是還完整？（C4）
8. 沒有任何一處要求使用者「聽聽看」。（C1）

## 8. 明確**不**在本文件範圍內（由設計端決定）

顏色、字體、字級、間距、圓角、陰影、材質感、視窗尺寸與比例、控制項長什麼樣
（旋鈕／滑桿／數字框都可以）、分頁或分區的方式、要不要有樂器插畫或動畫、
資訊層級的取捨、動效。

**唯一的風格性要求**：這是一個賣給音樂人的專業樂器軟體，不是玩具。
