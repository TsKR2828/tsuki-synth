## 0. 先講一件對不上的事（R2/R3/R4 誠實揭露）

需求原話說「原始參考 `uiux/TsukiSynth.html` 裡空靈鼓/揚琴有自己的模擬彈奏畫面（揚琴含左右手強弱與泛音設定）」。

我逐字讀完 `uiux/TsukiSynth.html` 全文＋它引入的四份 jsx（`components.jsx`／`engines.jsx`／`app.jsx`／`tweaks-panel.jsx`），並用 `git log --follow` 確認這批檔案在 repo 裡只有一次 commit（`91b9064 feat: visual overhaul — custom LookAndFeel matching React prototype`）。

**結論：這份參考 HTML 裡沒有任何揚琴或空靈鼓的「模擬彈奏畫面」。** 它是一份純控制面板原型——旋鈕（Knob）、下拉選單（ComboBox）、分頁、A/B 比較、MIDI 鍵盤——就是現在 `PluginEditor.cpp` 那套 UI 的設計藍本，兩邊逐條對得上（連 `TsukiLookAndFeel.h` 開頭都寫「Colour palette — matches uiux/TsukiSynth.html CSS exactly」）。原型裡沒有畫弦、沒有畫鼓面舌片、沒有左右手強弱這種東西，A/B 比較功能甚至連現行 C++ 版都沒做出來。

我用 `src/UiLocale.h` 交叉確認了「揚琴」「空靈鼓」在程式碼裡實際指什麼：

| 月月說的名字 | 對應到的現有引擎/子引擎 | 證據 |
|---|---|---|
| 揚琴 | Cimbalom 引擎（`ui_tab_cimbalom` 中文標籤＝「揚琴」） | `UiLocale.h:239` |
| 空靈鼓 | Chromatic 引擎的 `chr_sub_engine` 選項之一（英文 "Tongue Drum"，中文＝「空靈鼓」） | `UiLocale.h:88` |
| （揚琴的）泛音 | 找不到對應——揚琴（Cimbalom）完全沒有泛音參數 | 見下表 |
| （空靈鼓的）泛音 | Chromatic 的第三個子引擎「自訂泛音」（英文 "Custom"）：`chr_ratio_0..7` + `chr_amp_0..7`，8 組泛音比率＋幅度 | `PluginEditor.h:163-165`、`UiLocale.h:88` |
| 揚琴左右手強弱 | **完全不存在**——APVTS 裡沒有任何左右手/立體聲分軌參數 | 通篇搜尋 `src/` 無結果 |

也就是說：「泛音設定」這件事是真的、已經存在，但長在**空靈鼓**（Chromatic → Custom）身上，不是揚琴；「左右手強弱」則是兩邊都沒有的全新概念。這份提案會照月月的需求把「模擬彈奏畫面」設計出來，但誠實標注：

- 揚琴視圖：畫面示意 100% 可用現有參數驅動（材質/槌頭/敲擊點/弦數/解諧）。
- 空靈鼓視圖：畫面示意 100% 可用現有參數驅動，且「自訂泛音」子引擎的 8 組 ratio/amp 天生就適合畫成 8 片鼓舌，是這次設計裡對應最漂亮的一段。
- 「左右手強弱」：**標記為未溯源的新功能**，畫面可以先做出視覺佔位（兩個滑桿），但接了也不會動任何聲音——要讓它真的影響音色，需要先在 `PluginProcessor`/引擎裡新增 APVTS 參數與 DSP 邏輯，這超出「純 UI 提案、不改 JUCE 程式碼」的範圍，需要月月先拍板要不要做、怎麼做，再排進下一輪工作。

如果月月記得的畫面其實是另一個檔案或口頭設想，請直接說，我用那個當依據重畫。

## 1. 現況問題診斷

### 1.1 現行視窗尺寸（`PluginEditor.cpp` 常數，逐字讀取）

```cpp
constexpr int kW = 620;
constexpr int kH = 920;
...
setResizable (true, true);
setResizeLimits (540, 820, 1100, 1400);   // minW, minH, maxW, maxH
setSize (kW, kH);
```

- 預設視窗：**620 × 920**
- 可縮放範圍：寬 540–1100，**高 820–1400**
- 也就是說，這個外掛**最矮也要 820px 高**才能顯示完整——這是問題核心。

### 1.2 垂直堆疊的固定高度總帳

現行版面由上到下是單一直欄，每個區塊高度都在 `resized()` 裡寫死：

| 區塊 | 高度常數 | 值 (px) | 是否隨引擎變動 |
|---|---|---|---|
| 標題列 | `kTitleH` | 64 | 否，恆定 |
| Preset 列 | `kPresetH` | 50 | 否，恆定 |
| 引擎分頁 | `kTabH` | 42 | 否，恆定 |
| 巨集（Macro）8 旋鈕 | `kMacroH` | 104 | 否，四引擎都顯示同一排 |
| 引擎參數區 | 無常數，`area` 剩餘空間 | **可壓縮，但有下限** | 是，3～5 列視引擎/子引擎而定 |
| 效果區（Reverb/Delay/Comp） | `kEffectsH` | 126 | 否，恆定 |
| 失真＋EQ 區 | `kDistH` | 82 | 否，恆定 |
| 分析儀（Scope/Spectrum/Tuner） | `kAnalyzerH` | 86 | 否，恆定 |
| MIDI 鍵盤 | `kKeyboardH` | 84 | 否，恆定 |

**8 個固定區塊加總 = 64+50+42+104+126+82+86+84 = 638px**，這一段完全不會因為換引擎而變小。剩下的空間才輪到「引擎參數區」動態分配：

- 一般引擎（Cimbalom / FM Piano / Piano）：3 列參數
- Chromatic 選到「自訂泛音」子引擎：`numRows = 5`（`chrRatios[8]` + `chrAmps[8]` 要拆成 4 列 4 欄 + 1 列子引擎選單）

在視窗**下限 820px** 時，引擎參數區只剩 `820 − 638 = 182px`。自訂泛音模式要塞 5 列，每列高度 `(182 − 4×8) / 5 ≈ 30px`——一顆旋鈕連同標籤根本塞不進 30px，這個下限在 Chromatic 自訂泛音模式下其實已經是「理論可縮，實際擠爆」的假下限。

### 1.3 跟 Mac 實機螢幕對照

月月回報的現象「Mac 上鍵盤區被螢幕吃掉且無法調整」，換算成數字大概是這樣：

- 常見文書筆電（如舊款 13" MacBook Air/Pro）邏輯解析度是 **1440×900**，也就是垂直方向只有 **900px** 的「點」可用。
- macOS 選單列固定吃掉約 24pt。
- 外掛跑在 Standalone 或某些 DAW 的獨立浮動視窗裡，還要扣掉視窗自己的標題列/工具列，抓寬鬆一點也有 20–50pt。
- 算下來，實際可用高度大概落在 **816–850px** 之間。

而現行外掛的**最小高度是 820px**、**預設高度是 920px**——預設值本來就超過整台筆電的可用垂直空間，最小值也剛好卡在臨界點附近甚至更高。這解釋了兩件事：
1. 為什麼視窗一開起來鍵盤（在最底部）就被螢幕邊界吃掉——820～920px 在 816～850px 的可用高度裡根本放不下，OS/host 直接裁掉超出螢幕的部分，這個外掛沒有內部捲軸可以救。
2. 為什麼「無法調整」——`setResizeLimits` 的下限就是 820，使用者能拖的範圍完全沒有觸及會有幫助的更矮尺寸，怎麼拖都拖不進 816～850 的可用視窗。

**根因是版面模型本身**：目前是「單欄、8 個固定高度區塊由上疊到下」，總高度是所有區塊高度的總和，沒有任何一個環節允許「橫向並排換取垂直空間」。雙開門的核心價值正是在這裡：把直欄拆成兩扇並排的門，同一批控制項改用「寬度換高度」，才能把最小可用高度壓到明顯低於 820px。

## 2. 雙開門佈局規格

### 2.1 整體隱喻

視窗打開時像拉開一對對開門：**左門＝參數調整**、**右門＝樂器模擬面**。兩門中間有一條窄窄的「門縫」分隔線（用現有 `Clr::border` #2a2a4a，不新增顏色），共用頂部的標題列／Preset 列橫跨整個視窗寬度，不重複兩份。

```
┌──────────────────────────────────────────────────────────┐
│  TsukiSynth                                    語言 v1.x  │  ← 共用標題列 (跨滿版寬)
├──────────────────────────────────────────────────────────┤
│  ◀▶ [ PRESET ▼ ]                    Save  Init  *         │  ← 共用 Preset 列 (跨滿版寬)
├───────────────────────────┬──────────────────────────────┤
│  左門：參數調整              │  右門：樂器模擬面              │
│  ┌ ENGINE │ FX ┐ (子分頁)   │  ┌ 琴鍵 │ 揚琴 │ 空靈鼓 ┐     │
│                            │                              │
│  [Cim][Chr][FM][Piano]     │   （視選到的分頁顯示對應內容）  │
│  ── MACRO 8 旋鈕 ──         │                              │
│  ── 引擎參數 (2 欄) ──      │   ├ 琴鍵：MIDI 鍵盤 (全尺寸)  │
│    (FX 分頁時換成)          │   ├ 揚琴：撥弦/槌頭示意圖      │
│  ── Reverb/Delay/Comp ──   │   └ 空靈鼓：8 片鼓舌示意圖     │
│  ── Distortion/EQ ──       │                              │
│                            │   ── Analyzer (Scope/Spec/Tuner) ──│
└───────────────────────────┴──────────────────────────────┘
```

左門內容量最大（macro＋引擎參數＋效果全部塞在同一扇門），所以左門再切一層**子分頁**：「ENGINE」（引擎分頁＋Macro＋引擎專屬參數）與「FX」（Reverb/Delay/Comp/Distortion/EQ）。這一刀是縮高度的關鍵——不切的話左門自己就要垂直塞 104+引擎參數+126+82，跟現在半斤八兩。

右門常駐一條「樂器視圖切換」：**琴鍵 / 揚琴 / 空靈鼓** 三個分頁按鈕（樣式沿用現有 `.tab`/引擎分頁的視覺語言）。切到揚琴或空靈鼓時，畫面下方仍保留一條窄版鍵盤或至少「點擊示意圖＝觸發音符」的互動（見第 3 節），確保切到樂器視圖不會讓使用者失去彈奏能力。分析儀（Scope/Spectrum/Tuner）固定貼在右門底部，兩個分頁切換時都看得到——本來就是全域狀態，不屬於任何一個引擎的參數，跟著右門走比跟著左門走更合理（示波器是「聽聲音」的東西，樂器視圖是「彈奏」的地方，語意上放一起）。

### 2.2 響應式規則

雙開門是「夠寬才並排、不夠寬就收成單門＋切換鈕」的兩態設計：

- **雙門模式**（視窗寬度 ≥ 900px）：左右門並排顯示，比例約 46% / 54%（右門稍寬，留給樂器視覺插畫呼吸空間）。
- **單門模式**（視窗寬度 < 900px）：只顯示一扇門，標題列右側出現一顆「開另一扇門 ⇄」按鈕（沿用現有 icon-btn 樣式），點一下用類似 preset flash 的過場切換到另一扇門。這個模式對應現在最窄的使用情境（540px 寬），此時邏輯上跟現行「單欄直排」等價，但高度不再被鍵盤/樂器視圖以外的固定區塊拖垮，因為引擎參數已經被左門自己的 ENGINE/FX 子分頁拆開，不會同時全部攤開。

### 2.3 最小尺寸建議

| | 寬 | 高 |
|---|---|---|
| 最小（單門模式，貼近現行最窄寬度） | 620 | **560** |
| 預設（雙門模式） | 960 | 640 |
| 最大 | 1400 | 900 |

560px 的高度預算大致是：共用標題列＋Preset 列（≈100，比現行 64+50 略緊縮）＋門內子分頁列（≈36）＋內容區（剩餘）＋（單門模式下鍵盤或樂器視圖自己決定要不要收窄，不像現在鍵盤是全域固定 84px 墊底）。560px 遠低於現行的 820px 下限，且遠低於前述 816–850px 的 Mac 可用高度估算，這是直接解決月月回報問題的數字目標。實際切分留給 Phase 1 用真機（尤其是月月的 Mac）截圖迭代微調，這裡先定量級。

## 3. 揚琴（Cimbalom）與空靈鼓（Chromatic）視圖規格

以下逐項對照「現有 APVTS 參數」——所有互動元素都必須有對應參數才畫得出來，沒有對應的另外標註。

### 3.1 揚琴視圖（引擎：Cimbalom）

參考原型 `TsukiSynth.html` 裡的畫法慣例（旋鈕用 SVG 弧線＋中心圓，強調暖金色描邊、深色背景浮雕質感），畫面主體是一個梯形共鳴板，上面畫一排斜張的弦，兩端各有一道琴橋。

| 畫面元素 | 對應現有參數 | 互動方式 |
|---|---|---|
| 弦的數量 | `cim_num_strings`（弦數，1–5） | 視圖動態畫出對應數量的弦組；不新增互動，純視覺同步 |
| 弦的顏色/光澤 | `cim_material`（材質：鋼/銅/青銅/鋁/黃銅…） | 材質下拉選單改變時，弦的漸層色同步換（鋼＝冷灰白、銅＝暖橘、青銅＝深金） |
| 敲擊點高亮 | `cim_strike_pos`（敲擊點，0–100%） | 弦上畫一個可拖曳的光點，沿弦長軸移動；拖曳直接驅動 `cim_strike_pos`，效果等同現有旋鈕，但用「摸弦」的手感取代轉旋鈕 |
| 音高/鬆緊感 | `cim_detuning`（解諧，0–50¢） | 弦的張力線条角度輕微抖動幅度隨數值增加，視覺上暗示「走音」程度 |
| 槌頭材質 | `cim_hammer`（棉槌/氈槌/木槌/金屬槌） | 畫一支簡化槌頭圖示貼在敲擊點旁，依材質換描邊粗細/顏色 |
| 彈奏 | — | 點擊任一根弦＝觸發一個音符（音高依該弦在鍵盤上的映射，沿用 `keyboardState`），視覺上弦短暫發光，等同現行點鍵盤 |
| **左右手強弱** | **無對應參數（未溯源新功能）** | Phase 2 先畫兩個滑桿佔位（標「左手」「右手」），**不接任何 DSP**；要生效需先在 `PluginProcessor` 新增類似 `cim_hand_l_gain`/`cim_hand_r_gain` 的 APVTS 參數並讓 `CimbalomEngine` 依落點左右分配增益或音色，這是額外的音訊工程工作，需要月月先決定要不要做 |

### 3.2 空靈鼓視圖（引擎：Chromatic，子引擎依 `chr_sub_engine` 三選一）

主體畫一個圓形金屬殼（handpan 造型），中央一個「主音」圓點（ding），外圈依子引擎狀態畫不同東西：

**子引擎＝空靈鼓（Tongue Drum，預設）或水鑼（Water Gong）：**

| 畫面元素 | 對應現有參數 | 互動方式 |
|---|---|---|
| 鼓面材質光澤 | `chr_material`（木/玻璃/青銅/石） | 圓殼漸層色隨材質切換 |
| 鼓面尺寸 | `chr_size`（50–300mm） | 圓的半徑隨數值縮放（有上下限，畫面裁在合理範圍內） |
| 鼓皮厚度 | `chr_thickness` | 圓殼邊緣描邊粗細對應 |
| 敲擊點 | `chr_strike_pos` | 圓面上可拖曳的光點，同揚琴邏輯 |
| 激振方式 | `chr_exciter`（柔/中/硬/銳） | 槌頭圖示同揚琴，四級材質對應四種描邊 |
| 滑音（僅水鑼） | `chr_pitch_glide`，`enabledWhen: subengine === "Water Gong"` | 只有選到水鑼時才亮起一個「按下拖曳出滑音」的把手，其餘子引擎顯示為灰階不可互動（沿用現有 `knob-disabled` 視覺） |

**子引擎＝自訂泛音（Custom）——這是跟月月要的「泛音設定」對得最準的一段：**

| 畫面元素 | 對應現有參數 | 互動方式 |
|---|---|---|
| 8 片放射狀鼓舌 | `chr_ratio_0..7`（每片舌頭的泛音比率）＋`chr_amp_0..7`（每片的音量/強度） | 圓殼外圈畫 8 個舌片形狀（參考真實 handpan 的 tongue drum 造型），環繞排列；點擊某片舌頭跳出一個小面板，裡面是那片舌頭專屬的「比率」旋鈕＋「幅度」旋鈕，直接對應 `chr_ratio_N`/`chr_amp_N` 這一組 APVTS 參數 |
| 舌片大小 | 用該片的 `chr_amp_N` 值反映舌片描邊粗細/發光強度，數值愈大舌片視覺愈「活躍」 | 純視覺回饋，不是新參數，是既有 `chr_amp_N` 的另一種呈現方式 |
| 彈奏 | — | 點擊舌片＝依該片 `chr_ratio_N` 算出的音高觸發一個音符 |

這一段完全不需要任何新參數——8 片舌頭剛好對上現有 `chrRatios[8]`／`chrAmps[8]` 這兩個陣列（`PluginEditor.h:163-165`），是整份提案裡「視覺隱喻」跟「既有資料結構」貼合度最高的部分。

## 4. 實作分期

### Phase 1 — 佈局重排（低風險，純排版）
- 把現行控制項（一顆不改）搬進雙開門骨架：左門子分頁（ENGINE/FX）、右門分頁（琴鍵/揚琴/空靈鼓，但揚琴＝空靈鼓分頁先只放「敬請期待」佔位或直接顯示 MIDI 鍵盤，不畫插畫）。
- 更新 `setResizeLimits`／預設 `setSize` 到第 2.3 節的數字。
- 響應式雙門/單門切換邏輯。
- 驗收：所有現有旋鈕/下拉選單/preset/A-B（如果之後真的要做）在新版面下功能完全不變，只是位置換了。

### Phase 2 — 樂器模擬視圖（中風險，新繪圖元件）
- 畫揚琴視圖、空靈鼓視圖（含自訂泛音的 8 舌片子面板），依第 3 節逐項對應現有參數，用 JUCE `Graphics`／`Path` 繪製，風格比照 `TsukiLookAndFeel::drawRotarySlider` 的暖金弧線＋深色浮雕質感。
