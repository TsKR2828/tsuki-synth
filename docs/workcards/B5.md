# 施工卡 B5：木材正交異向常數入庫（schema 備料，非模型改動）

> 建立：2026-08-16
> 收件人：AI 工兵（無本次對話記憶）
> 定位：本卡**不做 Kirchhoff 板/梁的正交異向化**，也**不接共鳴板阻尼**。
> 本卡只做一件事：把 Wood Handbook FPL-GTR-190 的木材方向性常數，以
> fail-closed 的方式存進 `data/materials.json` + `MaterialDB.h`，讓之後
> 需要用到的人（B1 落地後的共鳴板工作）有現成、可溯源的資料可讀。
> 沒有任何程式碼路徑會在本卡完成後**消費**這批新資料——這是刻意的。

---

## 0. 一句話目標

在 `data/materials.json` 的 4 種木料（`wood_spruce`/`wood_maple`/`wood_birch`/
`wood_oak`）新增一個可選的 `orthotropic` 資料塊（9 個獨立正交異向常數 + 6 個
量測泊松比 + 交會含水率 `Mp`，全部逐字轉錄自文獻表格），`MaterialDB.h` 對它做
fail-closed 解析與驗證；不改變任何引擎的計算路徑，不改變任何既有 score 的渲染
結果（bit-exact，需證明）。

- **前置卡：B1（琴橋導納／共鳴板耦合，`docs/BRIDGE_ADMITTANCE_SOURCES.md`）。**
  **但本卡與 B2 不同：本卡的 schema/資料入庫工作實際上不依賴 B1 的程式碼存在**
  ——只依賴 `data/materials.json`／`MaterialDB.h` 現況（本卡開工前必讀，見 §1

  可以消費它，物理正確性的實際效益是零（`WOOD_ANISOTROPY_SOURCES.md` §6 結論）。

## 3. 要改的檔案與函式

- **`data/materials.json`**：對 `wood_spruce`／`wood_maple`／`wood_birch`／
  `wood_oak` 四個條目新增可選欄位 `orthotropic`（結構見 §5）。**其他 10 種
  材質不加這個欄位**（不是木材，正交異向不適用）。既有 `density`／
  `youngs_modulus`／`poisson_ratio`／`damping` 四個既有欄位**完全不動**。
- **`src/physics/MaterialDB.h`**：
  - `Material` struct 新增巢狀 `Orthotropic` struct 成員（§5 的欄位）。
  - `parseJson()` 新增：偵測 `orthotropic` 鍵是否存在；存在則**整塊**驗證
    （型別、正負號、上下界），任一子欄位不合法就讓**整個檔案**載入失敗
    （比照現行 `density`/`youngs_modulus` 等欄位的失敗即整檔拒絕邏輯，
    不是只拒絕那一個材質）；不存在則 `Orthotropic::present = false`，
    其餘欄位維持結構預設值，视为「這個材質沒有正交異向資料」（合法狀態，
    不是錯誤——本卡只替 4 種木料寫，其他材質本來就没有）。
  - 新增輔助函式或注解說明：**任何讀取 `Orthotropic` 資料的呼叫端，必須先檢查
    `present == true`；`present == false` 時所有數值欄位都是未定義用途的
    結構預設值，不得被當成「等向性當作 0」之類的隱含語意使用。**
- **不改的檔案（刻意，已登記）**：
  - `src/physics/PlateModel.h`／`src/physics/BeamModel.h`——Kirchhoff
    板/梁公式的正交異向化是「模型結構改動」（§11 已展開規模），不在本卡。
  - `src/engines/CimbalomEngine.h`／`ChromaticEngine.h`——沒有任何引擎邏輯
    改動。
  - `tools/physics_verify.py`——現有 `material_poisson_ratio()`／
    `stiff_string_oracle()` 只讀 `youngs_modulus`／`poisson_ratio`（純量），
    本卡不動這兩個既有欄位，這兩個函式不需要改。**若工兵發現非改不可，
    先停下確認為什麼**（可能代表誤觸了不該碰的路徑）。
  - `docs/WOOD_ANISOTROPY_SOURCES.md` 本身——溯源文件不因實作而改寫，
    最多在其 §8 狀態清單打勾。

## 4. 公式與常數

### 4.1 9 個獨立常數怎麼從文獻表換算成 JSON 欄位

`E_L` 直接沿用該材質現有的 `youngs_modulus`（`MATERIALS_SOURCES.md` 已文件化
為「縱向 E」）。其餘 8 個獨立量（`E_T`、`E_R`、`G_LR`、`G_LT`、`G_RT` 五個，
加上 6 個量測泊松比中選 3 個獨立的做法——**本卡不做這個化簡，理由見下**）
以 Table 5-1 的**比值**（`ET/EL` 等）與 Table 5-2 的**全部 6 個泊松比**逐字
存入，不做任何互易關係推算：

> `WOOD_ANISOTROPY_SOURCES.md` §3 原文明確警告「理想的互易關係
> （μij/Ei = μji/Ej）在實測上並非總是嚴格成立……不得用互易關係『修正』
> 表值」。因此本卡**存全部 6 個測得的泊松比**（不是只存 3 個「獨立」的再靠
> 公式推另外 3 個），忠實反映文獻的量測狀態，符合 Rule 4「量測值不得被推導
> 覆寫」的精神。

## 5. 新增參數/schema

### 5.1 `data/materials.json`（4 個木料條目，可選欄位）

```json
"wood_spruce": {
  "display_name": "雲杉 Spruce",
  "density": 450,
  "youngs_modulus": 12e9,
  "poisson_ratio": 0.37,
  "damping": { "eta": 7.0e-3, "beta_air": 3e-7, "gamma_radiation": 5e-5 },
  "orthotropic": {
    "source_species": "Spruce, Sitka",
    "moisture_content_pct": 12,
    "mp_percent": 27,
    "ratio_ET_EL": 0.043,
    "ratio_ER_EL": 0.078,
    "ratio_GLR_EL": 0.064,
    "ratio_GLT_EL": 0.061,
    "ratio_GRT_EL": 0.003,
    "poisson_LR": 0.372,
    "poisson_LT": 0.467,
    "poisson_RT": 0.435,
    "poisson_TR": 0.245,
    "poisson_RL": 0.040,
    "poisson_TL": 0.025
  }
}
```

`wood_maple`/`wood_oak` 的 `ratio_GRT_EL` 欄位**必須寫成 JSON `null`**（不是
省略、不是 `0`）——原表沒有這個量，`null` 是「文獻未列」的顯式標記；`0` 會被
未來的消費端誤讀成「RT 平面剪切模量為零」（物理上荒謬）。

| 欄位 | 型別 | 範圍 | 預設值 | 預設值來源 | fail-closed 行為 |
|---|---|---|---|---|---|
| `orthotropic`（整塊） | object，可選 | — | 不存在 | 非木材材質、或木材尚未補資料時的自然狀態 | 整塊不存在 = 合法（`present=false`）。整塊存在但任一子欄位型別錯/超界 = **拒絕整個 materials.json 載入**（沿用既有 `parseJson` 的 all-or-nothing 語意） |
| `source_species` | string，非空 | 必須是本卡 §4.2 表列 4 個學名之一 | — | 文獻表格樹種名（英文原文，作可追溯 key） | 空字串或不在允許清單 → 拒絕整檔 |
| `moisture_content_pct` | number | 恆為 12（Wood Handbook Table 5-1/5-2 的量測基準） | — | 文獻表格前言 | ≠12 → 拒絕整檔（本卡沒有任何來源支持別的基準值） |
| `mp_percent` | number | (0, 40] | — | Table 5-13 或「未列樹種假設 25」 | 越界 → 拒絕整檔 |
| `ratio_ET_EL`, `ratio_ER_EL` | number | (0, 1) | — | Table 5-1 | ≤0 或 ≥1 → 拒絕整檔（橫紋恆比順紋軟，這是正交異向木材的定義性質） |
| `ratio_GLR_EL`, `ratio_GLT_EL` | number | (0, 1) | — | Table 5-1 | 同上 |
| `ratio_GRT_EL` | number 或 `null` | (0, 1) 或 `null` | — | Table 5-1（`null`=原表未列） | 型別非 number 且非顯式 `null` → 拒絕整檔 |
| `poisson_LR`…`poisson_TL`（6 個） | number | [0, 1) | — | Table 5-2 | 越界 → 拒絕整檔 |

### 5.2 `MaterialDB.h`（C++ 端）

```cpp
struct Orthotropic
{
    bool present = false;                 // false = 這個材質沒有正交異向資料
    juce::String sourceSpecies;
    float moistureContentPct = 12.0f;
    float mpPercent          = 25.0f;
    float ratioET_EL = 0.0f, ratioER_EL = 0.0f;
    float ratioGLR_EL = 0.0f, ratioGLT_EL = 0.0f;
    bool  hasGRT = false;                 // false = 原表「—」，ratioGRT_EL 未定義
    float ratioGRT_EL = 0.0f;
    float poissonLR = 0.0f, poissonLT = 0.0f, poissonRT = 0.0f;
    float poissonTR = 0.0f, poissonRL = 0.0f, poissonTL = 0.0f;
};
```

加進 `Material` struct：`Orthotropic orthotropic;`（不影響既有欄位的記憶體
配置順序無強制要求，但建議放在 `damping` 之後，維持宣告順序與 JSON 欄位
順序一致，方便日後對照）。

## 11. 已知風險與地雷

- **最大的認知陷阱**：GATE 全綠、no-op 證明也過，會讓人有「這件事做完了、
  木材異向性已經支援」的錯覺。**事實是：目前這批資料完全是死資料，任何
  引擎的計算路徑都不讀它。** 完成本卡後的 `TODO.md`/`ROADMAP_PHYSICS.md`
  更新用字要非常精確（「schema 已備妥」而非「木材正交異向已支援」），
  避免誤導後續讀文件的人（或月月自己）以為音色已經改變。
- **Kirchhoff 公式改異向版的規模，此處攤開講清楚**（避免有人誤以為是小改動
  一起做掉）：`PlateModel::calculateModes()` 目前的特徵值表（`zeros[]`/
  `freeModes[]`，來自 Leissa NASA SP-160 Table 2.1/2.5）**是等向性圓板的
  解析解特徵值**，本身建立在 `D` 是純量、各方向彎曲剛度相同的假設上。
  正交異向圓板（`Dx ≠ Dy`，還有交叉項 `Dxy`）**沒有這種簡單的解析特徵值表**
  ——連「圓板」這個幾何本身在正交異向材料下都不再有 Leissa 那種乾淨的
  Bessel 函數解，通常要嘛簡化成矩形板（正交異向矩形板才有經典解析解族），
  要嘛用有限元素/Rayleigh-Ritz 數值解。這不是「換一組常數進現有公式」，
  是要重新選一族解、重新推導或重新查表。同理，`BeamModel` 現在的
  `E*I/(rho*A)` 若要考慮舌片同時有順紋/橫紋剛度（例如舌片是薄片而非細桿，
  存在扭轉/雙軸彎曲耦合），也不是單純換一個 `E`。**這是 §11 特別要求
  攤開講的「(b) 大」階段，本卡不做，未來要做需要一張獨立的、以正交異向板/梁
  解析解或數值解為主題的施工卡，且需要新的文獻搜尋（現有兩份溯源文件都
  没有提供這個解）。**
- **「(a) 小」階段（只給共鳴板用異向 D）目前也卡住，原因不是工程量而是
  資料**：`BRIDGE_ADMITTANCE_SOURCES.md` §2.1 的 `Y∞ = 1/(8√(D·ρs))`
  是**無限大等向性平板**的driving-point admittance 經典結果；其推導本身
  用到「彎曲波速在各方向相同」，正交異向板的彎曲波速是方向相依的
  （`c_B(θ)`），所以 `Y∞` 的正交異向推廣**不是**簡單把 `D` 換成
  `sqrt(Dx·Dy)` 就物理正確——這類幾何平均式子在某些聲學文獻上出現過，
  但**兩份現有溯源文件都沒有明確給出、驗證過這個推廣公式**（`Cremer,
  Heckl & Ungar, Structure-Borne Sound` 教科書原文列在引用清單但只取得
  摘要層級資訊，未取得全文對應章節）。**若之後要做 (a)，第一步是先確認
  這個公式能不能溯源到，找不到就不准自己湊一個「看起來合理」的近似公式
  套用（Rule 4）**，必須停下讓月月裁決是要授權一個明確標註為「推導/近似，
  非文獻」的版本，還是先補搜文獻。
- **selftest 反例最容易漏掉的一項**：`ratio_GRT_EL` 的 `null` 語意。如果
  工兵嫌麻煩把它簡化成「缺就填 0」，會在未來某個消費端悄悄引入一個物理上
  荒謬的零剪切模量，而且因為現在沒有消費端，這個 bug 不會被任何 GATE 抓到
  ——**必須靠測試反例（§7）在寫入當下就攔住**，事後靠執行期發現會太晚。
- **與 B1/B2 的 merge 順序**：如果 B1/B2 已經在同一個工作樹改動
  `data/materials.json`（例如未來新增 `bridge_admittance` 之類的欄位），
  本卡的 `orthotropic` 欄位與那些改動理論上互不相干（不同鍵名），但**還是
  要在動手前重新 `git diff data/materials.json` 看一眼現況**，避免對著
  自己以為的舊版本編輯造成合併衝突或蓋掉別人的欄位。
