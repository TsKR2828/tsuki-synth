# 施工卡 B3：弦阻尼律換第一原理（`beta_air`/`gamma_radiation` 零自由參數化）

> 建立：2026-08-16
> 收件人：AI 工兵（無本次對話記憶）
> 定位：把**弦**（Cimbalom/Piano，`StringModel`）的阻尼律裡兩個查無出處的擬合欄位

## 4. 公式與常數

### 4.1 要進程式的算式（逐條抄自 `docs/STRING_DAMPING_SOURCES.md` §2）

```
M         = (r/2) · √(ω/μa)                          ω = 2πf, r = 弦半徑 (m)

Q⁻¹_air   = (ρa/ρ) · [ √2/M + 1/(2M²) ]               ρ = 弦材料密度 (kg/m³)

Q⁻¹_visc  = 0.003 · E · ρ · π² · r⁶ · ω² / (4·T²)     E = 楊氏模數 (Pa), T = 張力 (N)

Q⁻¹_disl  = 1 / 18000                                  無量綱常數

Q⁻¹_total = eta + Q⁻¹_air + Q⁻¹_visc + Q⁻¹_disl        eta = MaterialDB::Damping::eta

1/T60(f)  = Q⁻¹_total · f / MaterialDB::kEtaToDecayRate
```

**關鍵化簡（務必用這個形式，不要另外引入 `ln(1000)` 字面值）**：因為
`MaterialDB::kEtaToDecayRate = 2.2 = ln(1000)/π`（已存在的常數，`eta` 項本來就是
`eta·f/2.2`），而 `1/T60 = π·f·Q⁻¹/ln(1000)` 代數上等於 `Q⁻¹·f/2.2`——所以
**新的三個機制可以先加總成一個 `Q⁻¹`，跟 `eta` 加在一起，再乘以同一個
`f/kEtaToDecayRate`**，不需要新引入 `π` 或 `ln(1000)` 常數，也不需要把
`eta` 項和新三項分開算兩次「1/T60 貢獻」再相加（兩種寫法代數等價，前者
少一次浮點運算且與既有 `internalFrictionRate()` 用同一把尺）。

### 4.2 新常數（R4 溯源）與註解範本

```cpp
// ── Cuesta & Valette (1988) 弦阻尼三機制的物理常數 ──
// 來源：docs/STRING_DAMPING_SOURCES.md §2（逐字轉錄自引用該研究的開放全文，
// Improved frequency-dependent damping for time domain modelling of linear
// string vibration, ICA 2016, NESS 專案）。

// 空氣密度，標準大氣（ISA，海平面，15°C）。文獻表列常數，非量測、非推導。
static constexpr float kAirDensity = 1.225f;               // kg/m^3

// 空氣運動黏度。docs/STRING_DAMPING_SOURCES.md §2 表列「論文用 1.619e-5」，
// 逐字轉錄自 Cuesta & Valette (1988)（經 ICA 2016 全文引用）。
static constexpr float kAirKinematicViscosity = 1.619e-5f; // m^2/s

// 位錯（dislocation）損耗，頻率無關的擬合 Q^-1。docs/STRING_DAMPING_SOURCES.md
// §2：原文無法從量測資料區分位錯損耗與熱傳導損耗，兩者擬合同樣好，取此值。
// 這是原始文獻的擬合常數本身（不是本專案自己擬合的），故仍符合 Rule 4
// 「文獻」類來源，但注意它是單一數字、不隨材質變化（見 §11 風險）。
static constexpr float kDislocationQInv = 1.0f / 18000.0f; // 無量綱
```

`stringAirViscDislQInv()` 建議實作（**先讀 §1 第 3 步確認的實際簽名，
半徑/張力參數名以現況為準，這裡只是示意**）：

```cpp
/** Cuesta & Valette (1988) 弦阻尼空氣黏滯＋黏彈性＋位錯三機制，零自由參數。
 *  見 docs/STRING_DAMPING_SOURCES.md §2。只適用圓截面弦（r^6/r^2 幾何內建），
 *  不適用 Beam/Plate。回傳值是三項相加的 Q^-1（無量綱），與 eta 同一把尺，
 *  呼叫端把它跟 eta 加在一起再乘 f/kEtaToDecayRate（見本檔 decayTimeForFrequency）。
 */
static float stringAirViscDislQInv (float frequency, float radius, float tension,
                                     const MaterialDB::Material& material)
{
    if (frequency <= 0.0f || radius <= 0.0f)
        return 0.0f; // 無效輸入時不貢獻，交由既有 denominator>0 保護接手

    const float omega = juce::MathConstants<float>::twoPi * frequency;
    const float M = (radius * 0.5f) * std::sqrt (omega / kAirKinematicViscosity);
    const float qInvAir = (kAirDensity / material.density)
        * (std::sqrt (2.0f) / M + 1.0f / (2.0f * M * M));
    const float qInvVisc = 0.003f * material.youngsModulus * material.density
        * juce::MathConstants<float>::pi * juce::MathConstants<float>::pi
        * std::pow (radius, 6.0f) * omega * omega
        / (4.0f * tension * tension);
    return qInvAir + qInvVisc + kDislocationQInv;
}
```

**不要**把這個函式的回傳值直接當成獨立的 `1/T60` 貢獻去跟 `eta` 項的
`1/T60` 貢獻相加（那是兩次除法、容易在化簡時弄錯係數）；照 §4.1 的化簡，
在 `decayTimeForFrequency()` 內把它跟 `eta` 加總成一個 `Q⁻¹_total` 再統一
乘 `f/kEtaToDecayRate`。

| （無新增 score/UI 參數） | — | — | — | — | 弦半徑/張力已存在於 `StringModel::Params`，不需要新的使用者可見參數 |

**遷移方式（照抄 `MaterialDB.h` 現行 `alpha`→`eta` 的寫法）**：

```cpp
// Fail-closed on the pre-B3 schema: a file that still carries the bare
// `beta_air`/`gamma_radiation` keys is REJECTED rather than silently
// reinterpreted as the renamed beam_plate_* fields — those two names now
// mean "Beam/Plate-only" and no longer feed StringModel at all, so a file
// written for the old schema must not load until it is explicitly migrated.
if (dampObj->hasProperty ("beta_air") || dampObj->hasProperty ("gamma_radiation"))
    return false;
```

放在既有 `hasProperty ("alpha")` 檢查旁邊，同一個 `if` 或緊接著的獨立
`if`，效果等價；連同下面讀取鍵名的 `finiteNumber(...)` 呼叫改讀新鍵名。

## 11. 已知風險與地雷

- **最大風險：`Q⁻¹_disl`（1/18000）可能與既有 `eta`（Phase H 已溯源的材質
  損耗因子）物理上重疊，對低 `eta` 材質造成不小的額外阻尼**。兩者在
  `1/T60` 裡都是純 `f¹` 項、都直接加總，係數換算後：
  `Q⁻¹_disl` 貢獻 = `(1/18000)`，`eta` 貢獻 = `eta` 本身（同一把尺，見 §4.1）。
  以 materials.json 現值算，`(1/18000)/eta` 佔比：steel（eta=2e-4）
  **≈27.8%**、aluminum（eta=1e-4）**≈55.6%**、bronze/glass/brass
  約 5～7%，wood/iron/rubber 皆 <1%。**steel 和 aluminum 是本卡對音色影響
  最大的兩個材質**，不是「零星個案」。這不是工兵可以自己決定「加或不加
  `Q⁻¹_disl`」的問題——**兩種做法都有物理依據上的合理性**（原公式明寫
  三項相加；但 `eta` 也已是月月核准、GATE 驗證過的材質溯源值）。**本卡的
  預設做法是照原公式全部加總**（因為這是任務指定的公式，不是工兵自選），
  但 §9 的 Rule 10 報告**必須把這個佔比表攤在月月面前**，不能悄悄加總就
  算數。若 steel/aluminum 的實際渲染音色變化在 6 首代表曲目裡明顯到需要
  月月介入判斷，**先完成 GATE 與報告，在報告裡明確提問，不要自己決定
  回退或調整**。
- **`damping_override` 錨點保證會被打破**：B2（及更早的 eta 寬頻化）刻意
  做到「32 首用 `damping_override` 的樂譜在 MIDI 60 錨點上 T60 逐位元不變」。
  B3 因為新增了跟頻率相關的三機制項，這個保證**必然**被打破（哪怕變化很
  小）。這是已知、預期的副作用，不是 bug，但必須在 Rule 10 報告裡誠實
  列出數字（§9 第 6 項），不能略過不提。
- **函式簽名變動的擴散面**：`decayTimeForFrequency()` 新增 `radius` 參數
  後，任何目前呼叫它的地方都要跟著改——本卡已列出 §3 表格裡的全部已知
  呼叫點（CimbalomEngine.h 4 處、tests 兩個檔案共約 7 處），但**若 B1 已經
  改過簽名或新增了呼叫點，以工兵實際 `grep -rn "decayTimeForFrequency"`
  的結果為準，不要相信本卡列的行號**（行號可能因 B1/B2 的改動而偏移）。
- **Beam/Plate 絕對不能被牽動**：改欄位名時容易手滑漏改或改錯一處，導致
  `BeamModel.h`/`PlateModel.h` 編譯失敗或讀到未初始化值。改完後這兩個檔案
  的 diff 應該**只有欄位名，沒有任何數字或運算子變化**——這是自我檢查的
  具體判準，不是「大致對」。
- **corpus 可能不只 Cimbalom/Piano 曲目受影響**：休止 RMS 邊際檔（歷史上
  `summer_m2`/`summer_m3`）對任何 T60 變化都敏感，即使那首曲子主要用
  Chromatic 引擎，只要有一軌用了 Cimbalom/Piano 也可能被牽動。跑 corpus
  前不要預設「只有弦音色曲目需要看」。
- **`--t60` 容差是 0.5–2.0 判定制，已經很寬**——若弦引擎的量測/模型比值
  仍落在容差內，不代表「模型精確」，只代表沒有觸發 GATE 失敗。不要把
