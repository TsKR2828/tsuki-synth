## 4. 公式與常數

### 4.1 三個新常數表（放在 `HammerImpulse.h`，`public:` 區塊，仿現有
`kTauCCotton` 等的寫法）

```cpp
/// 鋼琴槌氈非線性接觸律 F = K * delta^alpha 的逐音錨點。
/// 來源：Woodhouse, Euphonics §12.2.1 Table 2（經 Hall & Askenfelt 量測，
/// Chaigne & Askenfelt 用於模擬），轉引自 docs/HAMMER_CONTACT_SOURCES.md §2.1。
/// K 的單位是 N*m^-alpha —— 隨 alpha 而變，這是原表明載的性質不是筆誤。
/// 只有三個錨點（C2/C4/C7），中間音／範圍外音的內插與外推規則見
/// alphaForPianoNote()/logKForPianoNote() 的實作與註解。
static constexpr int   kPianoKAlphaAnchorMidi[3]  = { 36, 60, 96 }; // C2, C4, C7
static constexpr float kPianoHammerK[3]           = { 4.0e8f, 4.5e9f, 1.0e12f };
static constexpr float kPianoHammerAlpha[3]       = { 2.3f, 2.5f, 3.0f };

/// 槌質量 C1-C8，來源：Woodhouse Euphonics §12.2.1 Table 1（Conklin 與
/// Hall & Askenfelt 轉引），docs/HAMMER_CONTACT_SOURCES.md §2.2。單位 kg。
static constexpr int   kPianoMassAnchorMidi[8] = { 24, 36, 48, 60, 72, 84, 96, 108 };
static constexpr float kPianoHammerMassKg[8]   =
    { 0.012f, 0.011f, 0.010f, 0.009f, 0.008f, 0.007f, 0.006f, 0.005f };
```

### 4.2 內插規則（**這是月月要看的登記項，不是工兵自己選完就算**）

- 獨立變數用 **MIDI note number**（等價於 log2(frequency)，錨點間距不等
  不影響分段線性內插的正確性）。
- `alpha(note)`：在 `kPianoKAlphaAnchorMidi` 三點之間做**分段線性內插**；
  超出 [36, 96] 範圍（即 C1、C8）**不外插，夾在最近錨點**（`alpha(24)=alpha(36)=2.3`，
  `alpha(108)=alpha(96)=3.0`）——這是文件建議的保守選項
  （HAMMER_CONTACT_SOURCES.md §2.1：「α 隨音高單調上升」，flat 外推不會違反
  這個單調性，線性外推可能沖出已知範圍，不用）。
- `K(note)`：對 `log10(K)` 做同樣的分段線性內插（不是對 K 本身線性內插——
  K 跨 3 個數量級，線性內插會嚴重失真），範圍外同樣 flat 夾住。
  （文件依據：§2.1「log K 近似線性」。）
- `mass(note)`：對質量本身（不取 log）做分段線性內插，`kPianoMassAnchorMidi`
  8 個錨點覆蓋 C1–C8，範圍外一樣 flat 夾住。
- **這條內插規則本身是本卡新增的建模決策，不是文獻原文**。完成後的
  Rule 10 報告與 TODO.md 更新裡要明寫「內插規則：alpha/log K 對 MIDI note
  分段線性、範圍外 flat 外推」這一句，讓月月看得到、之後想改可以直接改。

### 4.3 解出 tau_c 的公式

推導（`HAMMER_CONTACT_SOURCES.md` §3，只到比例關係，**沒有給絕對前置係數**）：

```
tau_c(note, v) ∝ [ m(note) / K(note) ]^(1/(alpha(note)+1)) * v^( 2/(alpha(note)+1) - 1 )
```

**絕對量級不可以自己編一個前置係數**——文件沒推出解析解的常數項（那需要
解 F=Kδ^α 運動方程的相位積分，本文件未提供、Rule 4 禁止編造）。做法：
把這個比例關係**錨定在既有、已溯源的絕對量級**上，即現有
`kTauCFelt = 2.0ms`（Askenfelt & Jansson 直接量測值，`HammerImpulse.h`
檔頭已引用）在 **A4（MIDI 69）、velocity=0.5** 這一點的既有校準值。

```cpp
// g(note, v) = [m(note)/K(note)]^(1/(alpha(note)+1)) * v^(2/(alpha(note)+1) - 1)
// tau_c_piano(note, v) = kTauCFelt * g(note, v) / g(69, 0.5)
//
// 這個錨定選擇是本卡的設計決策，不是文獻數字：文獻只給出比例關係
// （HAMMER_CONTACT_SOURCES.md §3），沒有給絕對前置係數。用既有
// kTauCFelt（Askenfelt & Jansson 量測，已在本檔頂端引用）在 A4/v=0.5
// 錨定，使新公式在這一點與舊校準完全重合，其餘音高/力度的「相對形狀」
// 才是本卡真正換成物理推導的部分。這個錨點選擇本身要在完成報告裡
// 明寫，供月月覆核。
```

`v` 的定義沿用既有 `tauCForStrike()` 的 `juce::jlimit(0.02f, 1.0f, velocity)`
（0-1 正規化 MIDI velocity proxy，不是真實 m/s——這是既有架構的限制，
本卡不解決，只沿用）。

### 4.4 力度指數對照表（供實作自我核對，來源 `HAMMER_CONTACT_SOURCES.md` §3）

| `alpha` | 力度指數 `2/(alpha+1) - 1` |
|---|---|
| 2.3（C2） | −0.394 |
| 2.5（C4） | −0.429 |
| 3.0（C7） | −0.500 |

現行 `tauCForStrike()` 是固定 `-0.2`（對應純赫茲 α=1.5，不是鋼琴氈，見
`HAMMER_CONTACT_SOURCES.md` §4）。新函式的指數必須**隨音高變化**，不是
換一個固定數字。實作完成後可以寫一個小驗證：在 C2/C4/C7 三個錨點上
數值算出的力度指數應與此表誤差 < 1e-4（純代數驗證，不是渲染判定）。

### 4.5 安全 clamp（工程用，非 §6 容差，可自行訂但要寫理由）

新函式輸出的 `tau_c` 建議 clamp 在 `[0.3ms, 8ms]`——即現有 Cotton(6ms)~Metal(0.2ms)
四檔查表涵蓋的範圍再留一點餘裕，防止內插/外推在極端音高組合出病態值。
這不是 §6 登記容差，工兵可以自己定，但**必須在程式碼註解寫清楚這是工程安全
帶而非文獻值**，不可以讓它悄悄變成事實上的容差放寬。

## 5. 新增參數/schema

**本卡不新增任何 score JSON 欄位、不新增 schema、不新增 CimbalomParams 成員。**
新函式的輸入（`midiNote`、`velocity`）都是既有介面已經有的量。

`hammer`/`hammerIdx` 判斷 Felt 的邏輯：
- `startNote()`（plugin 即時路徑）：`pHammerHardness` 是連續 float 0~3，
  用 `std::round(hammer) == 1` 判斷是否落在 Felt 檔位附近（±0.5）。
  fail-closed：非 Felt（round != 1）一律走原本 `tauCForNote()`，不套新公式。
- `noteOn()`（CLI/score 路徑，也是 GATE 唯一覆蓋的路徑）：`hammerIdx` 已經是
  精確 int（`cimbalomExciterFromString()` 產生的 enum cast），直接
  `hammerIdx == 1` 判斷，不需要 round。
- **這兩處的判斷式必須一致（都是「精確落在/貼近 Felt」才套新公式）**，
  否則同一顆音符在 plugin 與 CLI 渲染會不一致，違反可重現性支柱。

## 7. 測試要新增什麼

在 `tests/physics_models_repro.cpp` 新增函式 `testPianoHammerContactSolver()`，
仿現有 `testHammerSpectrum()` 的 `CHECK` 風格，並在 `main()` 註冊呼叫。至少要有：

1. **錨點重現**：`pianoHammerTauC(69, 0.5f)` 與 `HammerImpulse::kTauCFelt`
   誤差 < 1e-4（§4.3 錨定的直接驗證）。
2. **力度指數方向性**：`pianoHammerTauC(60, 0.9f) < pianoHammerTauC(60, 0.1f)`
   （速度越快接觸時間越短，Hertz 型接觸的基本方向）。
3. **力度指數量級核對**（§4.4 表的代數驗證，不靠渲染）：分別在
   MIDI 36/60/96 取兩個 velocity 點算出的
   `log(tauC(v2)/tauC(v1)) / log(v2/v1)` 應分別逼近 −0.394/−0.429/−0.500，
   誤差 < 1e-3。
4. **內插單調性**：`alphaForPianoNote(midi)` 對 midi 36→96 之間任意兩個
   遞增的 note，回傳值不遞減（單調性是文件明講的物理排序，見 §2.1）。
5. **內插邊界 flat 外推**：`alphaForPianoNote(24) == alphaForPianoNote(36)`、
   `alphaForPianoNote(108) == alphaForPianoNote(96)`（同理驗 `logKForPianoNote`、
   `hammerMassForPianoNote`）。
6. **反例（必須有，比照 `physics_verify.py --selftest` 的作法）**：
   構造一個「如果內插規則被錯改成對 K 本身線性內插（不取 log）」的對照
   計算，證明目前實作在 C2→C7 中點（約 MIDI 66 附近，需按 §4.2 規則算出
   對應的 `logKForPianoNote` 值）明顯不等於「錯誤版本」的線性內插值
   （兩者應相差超過一個數量級，因為 K 跨 3 個數量級）。這一條的目的是
   把「不小心對 K 線性內插而不是對 log K 線性內插」這個最容易犯的錯
   釘死成一個會 FAIL 的迴歸測試。
7. **Felt 判斷邊界**：非 Felt hardnessIndex（0/2/3 及 round 後落在這三者
   的小數值，例如 1.6）不得觸發新函式——這條在 C++ 單元測試層級測
   `std::round` 判斷式本身即可，不需要整個渲染管線。

## 11. 已知風險與地雷

- **最大風險**：F3 velocity 判定（§6「velocity ×2 電平」）。2026-08-06
  那輪就因為能量預估帶進實際 `tau_c(velocity)` 被抓到 tongue_drum +4.72dB
  FAIL；本卡的力度指數比那輪的 `-0.2` 更陡（最深到 `-0.500`），**在 C7
  這種高音上尤其危險**，因為基頻本身已經很高，`forceSpectrumMagnitude`
  在陡峭 tau_c(v) 下對基頻本身的影響也可能不再接近 1。這正是為什麼
  §6 步驟 5 明確要求先看實測數字，不准先斬後奏。
- `kCimbalomAttackEnergyRefA4`（loudness 補償錨點）是在 **Wood exciter**
  下量測的常數，理論上不會被本卡改動觸碰到，但這是一個容易搞混的地方
  ——如果工兵誤以為要跟著 Felt 的 tau_c 改動重新量測這個常數，量出來的
  新數字會是錯的參照點（因為那個常數的定義是 Wood，不是 Felt）。
- K 的單位隨 α 而變（N·m^-α）：**絕對不要**把三個錨點的 K 直接拿來做
  「K 對 K」的線性內插或外插數值比較——量綱不同，比較沒有意義；只能
  對 `log10(K)` 做內插（§4.2 已明講，這裡再強調一次因為是最容易犯的錯）。
- Stulov 遲滯參數（`F0=8800 N/mm`、`p=3.95`）**不可以**和本卡的純冪律
  `alpha=2.3~3.0` 混用或互相代入——兩者是不同模型的不同指數，
  `p` 是含遲滯模型的彈性指數，不是冪律 `alpha` 的另一種寫法。
  本卡刻意不做遲滯（見 §12 說明），這條是防止工兵「順手」把兩組數字
  湊在一起用。
- 這批資料是**鋼琴專屬**（氈槌）。`Chromatic` 引擎（tongue drum / water
  gong）的槌具接觸參數在 `TODO.md` D2 完成前**未知**，本卡不得套用，
  也不得因為「反正公式差不多」就把 K/α/mass 常數借去用在 Chromatic 上
  ——那是把測到的別的物體的常數安到另一個物體上，直接違反 Rule 4。
